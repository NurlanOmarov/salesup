# Ручные SEO-настройки в админке — план и AI-режимы

_Дата: 2026-07-16. Продолжение `docs/SEO-AUDIT.md`: аудит закрыл технический фундамент (метаданные, structured data, sitemap/robots), этот документ — про **ручное управление SEO из админки** (аналог Yoast/RankMath) и **AI-ассистенты** поверх него._

## Философский принцип (отличие от WordPress)

В WordPress человек пишет метаданные с нуля — плагин лишь подсказывает. У нас другое: **фабрика курсов + AI-критик уже генерируют SEO** (правило 5). Поэтому админ-слой — это **override/тюнинг поверх AI**, а не первичное авторство:

- поле пустое → берётся сгенерённое фабрикой / глобальный дефолт;
- поле заполнено вручную → приоритет у ручного значения.

Из этого же следует, где AI полезнее всего (см. раздел «AI-режимы»).

## ✅ Сделано (P0, 2026-07-16)

**Глобальные SEO-настройки без деплоя** — раздел `/admin/seo`.

- Модель `SeoSettings` (singleton) + миграция `..._seo_settings_and_course_overrides`.
- `src/lib/seo/settings.ts` — кэш-геттер (`unstable_cache`, тег `seo-settings`, сброс при сохранении).
- Раздел `src/app/(owner)/admin/seo/` — форма с **SERP-превью** и **счётчиками длины** (title ≤ 60, description ≤ 155, цветовые зоны).
- Поля: шаблон title, дефолтные title/description, соцпрофили (→ `sameAs`), подтверждение прав (**Google Search Console / Яндекс.Вебмастер**), маркетинговые счётчики (**GA4 / Яндекс.Метрика**).
- **AI-черновик метаданных** (`src/lib/seo/ai.ts`, Anthropic Haiku, operation `seo:meta` → учёт в LlmUsage) — кнопка «AI-черновик» в форме.
- Подключение в `layout.tsx` (`generateMetadata` из настроек, `verification`, `sameAs` в `EducationalOrganization`).
- Счётчики — `src/components/analytics/marketing-analytics.tsx`, вставляются **только в `(marketing)`-layout** (D-002: своя `Event` — источник истины; внешние счётчики — маркетинговый слой; в кабинет ученика не подключаются — правило 9, ПДн).
- Per-course override-поля добавлены в схему: `ogTitle`, `ogDescription`, `canonicalPath`, `focusKeyword`, `seoNoindex` (форма курса — P1).

**Про счётчики (ответ на вопрос владельца):** свой счётчик (`Event`) — источник истины для продуктовых метрик; GA4/Метрика имеют смысл только на публичных страницах для анализа трафика анонимов (для КЗ актуальна Метрика). Для SEO важнее не GA, а Search Console/Вебмастер — их verification-поля уже в форме.

> ⚠️ **Развёртывание:** миграция создана как файл — применить `pnpm db:migrate` на поднятой БД (локально/VPS), там же прогнать живой рендер `/admin/seo` и мету главной. На момент реализации локальная БД (`localhost:5433`) была недоступна — код проверен `typecheck` + `lint`.

## ✅ P1 — Per-course SEO в карточке курса (2026-07-16)

Форма курса (`src/app/(owner)/admin/courses/[id]/edit-form.tsx`) переиспользует `SerpPreview`/`CharCounter`:

- SERP-превью + счётчики для `seoTitle`/`seoDescription` (placeholder показывает фолбэк на title/subtitle);
- поля `ogTitle`/`ogDescription`, `focusKeyword`, override `canonicalPath`, тумблер `seoNoindex`;
- кнопки **«AI-черновик»** (`generateMetaAction`) и **«Проверить SEO»** (`scoreMetaAction`);
- новые поля в схеме курса; `updateCourseAction` их сохраняет;
- страница курса `generateMetadata`: `robots: { index: !seoNoindex }`, `openGraph.title/description` из og-полей, `alternates.canonical` из `canonicalPath`.

## ✅ P2 — Менеджер редиректов (2026-07-16)

- Модель `Redirect { from @unique, to, hits }` + миграция.
- `src/lib/seo/redirects.ts` — `resolveRedirect` (best-effort `hits++`), `normalizePath`.
- Страница `/admin/seo/redirects` (`redirects-manager.tsx`) — добавить/удалить, счётчик срабатываний.
- Резолвинг — в `courses/[slug]/page.tsx` через `permanentRedirect` (308), когда slug не найден (главный кейс: фабрика переименовала курс).
- **Ограничение:** резолвинг реализован для `/courses/*` на уровне приложения — не в edge-middleware (там нет Prisma; auth-middleware держим чистым). Site-wide редиректы для произвольных путей → потребуют Node-runtime middleware, вынесено на будущее (для MVP публичных путей мало).

## ✅ P3 — AI-скоринг вместо чеклиста Yoast (2026-07-16)

Кнопка **«Проверить SEO»** (`scoreMeta` в `src/lib/seo/ai.ts`, Anthropic Haiku, operation `seo:score`): балл 0–100 + список проблем и рекомендаций по title/description/фокус-ключу с учётом реального содержания курса. Информационный сигнал (не блокирует публикацию — её контролирует критик контента, правило 5).

## ✅ Embeddings — каннибализация (2026-07-16)

- `src/lib/seo/semantic.ts` — эмбеддинг «SEO-текста» курсов на лету батчем (`embedDocuments`, OpenAI) + cosine в JS (курсов мало → без хранения векторов).
- `analyzeCannibalization()` — пары курсов с близостью ≥ 0.86 (конкурируют за один запрос); виджет `cannibalization.tsx` в `/admin/seo`, запуск по кнопке (контроль расхода API, правило 10).
- `relatedCourses(courseId)` — готова для блока «связанные курсы»/перелинковки (осталось подключить в UI курса).

## 🤖 AI-режимы: где ещё задействовать (два движка)

Ключевое: **Anthropic = генерация/оценка текста**, **OpenAI = только embeddings** (D-001, `text-embedding-3-small`, 1024, cosine, pgvector). Embeddings уже считаются фабрикой для RAG — тот же индекс бесплатно открывает SEO-фичи, которых у Yoast нет вовсе.

### На Anthropic (генерация/критика)

1. **AI-черновик метаданных** — ✅ сделано (`generateMeta`).
2. **SEO-критик** (P3) — балл + рекомендации по title/description.
3. **AI alt-тексты** для обложек/картинок (доступность + image SEO) — Haiku по названию курса.
4. **Črновик текста для thin-страниц** `/offer`, `/privacy` (аудит п.7 — сейчас `noindex`), под контроль критика.
5. **Draft контент-хаба/блога** (аудит п.11) — если вернёмся к блогу: генерация статей-кластеров под запросы.

### На OpenAI embeddings (семантика — уникально для нас)

6. **Умная перелинковка** (аудит п.6): для курса/страницы найти семантически близкие через cosine по существующему индексу эмбеддингов → предложить владельцу блок «связанные курсы» / внутренние ссылки. Не эвристика по словам, как в Yoast, а по смыслу.
7. **Детектор каннибализации**: два курса с высокой cosine-близостью title/description конкурируют за один запрос в выдаче → предупреждение в `/admin/seo` («курсы A и B борются за один интент, разведите фокус-ключи»). Yoast этого не умеет.
8. **Кластеризация фокус-ключей**: сгруппировать курсы/страницы по смысловым кластерам → карта тем, дыры в покрытии (какие интенты не закрыты ни одной страницей).
9. **Keyword ↔ контент match-score**: насколько `focusKeyword` семантически соответствует реальному содержанию страницы (эмбеддинг ключа vs эмбеддинг описания) — честная замена «плотности ключа».

**Реализация 6–9:** отдельный модуль `src/lib/seo/semantic.ts` поверх `embedQuery`/`toVectorLiteral` и pgvector-запросов (как в `lib/ai/rag.ts`); тяжёлые расчёты — фоновой Job (правило 8, идемпотентность), результат — виджеты в `/admin/seo` и строки в еженедельном дайджесте (zero-touch: не задача человеку, а информация).

## ✅ Дозакрытие пробелов (2026-07-16, вторая итерация)

- **OG-картинки вручную**: загрузка per-course (`og/<courseId>/…`) и глобально (`og/site/…`, `SeoSettings.defaultOgKey`); отдача через file-convention `opengraph-image.tsx` (кастом приоритетнее satori-генерации, фолбэк при сбое), превью в админке через публичный `/api/og-image/<courseId>`.
- **Связанные курсы** на странице курса: `lib/seo/related.ts` — семантический подбор с кэшем сутки (`unstable_cache`, тег `related-courses`) и фолбэком на «другие опубликованные» при недоступности OpenAI (публичный рендер не зависит от внешнего API).
- **Журнал 404 + site-wide редиректы**: модель `NotFoundHit` (агрегат по пути), catch-all `(marketing)/[...nf]` — сперва `resolveRedirect` (308 для ЛЮБОГО публичного пути, не только курсов), иначе запись в журнал; UI в `/admin/seo/redirects` («Редирект» из строки 404 заполняет форму; создание редиректа чистит журнал). Фильтры шума: расширения ассетов + служебные метадата-пути.
- **Гейтинг middleware изменён** (`auth.config.ts`): приватные зоны заданы явно (`/app`, `/admin`, `/change-password`); неизвестные пути идут в приложение и получают честный 404/308 вместо редиректа на логин (SEO-корректность; защита контента — в зонах и `lib/access`, правило 1).
- **AI-довески**: `completeVision` в `lib/ai/anthropic.ts`; **alt-тексты обложек** по самой картинке (vision, поле `Course.coverAlt`, рендер на странице курса); **карта тем** (`keywordClusters`, виджет в `/admin/seo`); **match-score «ключ ↔ контент»** (`keywordMatch`, показывается при «Проверить SEO» в карточке курса).
- **UX AI-предложений**: ничего не перезаписывается молча — карточка «было → станет» (`ai-suggestion.tsx`), кнопки «Применить»/«Отклонить», «Вернуть как было» после применения; в обеих формах добавлена кнопка **«Отменить изменения»** (сброс к сохранённому).
