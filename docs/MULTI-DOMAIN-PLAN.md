# MULTI-DOMAIN-PLAN.md — четыре домена на одном сервисе (BY / KZ / RU / UZ)

> Один сервис (NAT-VPS `93.127.131.216`, внутр. `192.168.122.10`), одна БД, одна медиатека —
> и четыре самостоятельных домена под четыре рынка. Дополнительных контейнеров и второго
> сервера нет. Решение — D-013 в `docs/DECISIONS.md`.

| Рынок | Домен | DNS | Панель (Add Domain) | Витрина |
|-------|-------|-----|---------------------|---------|
| Беларусь (канонический) | `study.activesales.by` | ✅ | ✅ работает | RU, цены в Br |
| Казахстан | `study.activesales.kz` | ✅ | ✅ работает | RU + KK (`/kk`), цены в ₸ |
| Россия | `study.sales-active.ru` | ✅ | ✅ работает | RU, цены в ₽ |
| Узбекистан | `study.activesales.uz` | ✅ A → `93.127.131.216` | ⏳ **осталось владельцу** | RU + UZ (`/uz`), цены в сумах |

Домен для РФ — `sales-active.ru` (не `activesales.ru`: там DNS у reg.ru, но поддомен заведён
в зоне `sales-active.ru`, NS `activeby.net`). Узбекская зона `activesales.uz` — NS `hoster.by`,
запись `study` уже указывает на наш сервер.

Список доменов в коде — `src/lib/seo/site-hosts.ts`: добавление страны = одна строка там
(хост, hreflang, гео-строка первого экрана, валюта витрины) + страновой профиль в
`src/content/legal/country.ts` + DNS + «Add Domain» в панели. Разрезы SEO-настроек в админке
и hreflang строятся из этого же списка, вручную их дополнять не нужно.

## 1. Что осталось сделать владельцу

**Панель Database Mart → Website Management → «Add Domain»** для узбекского домена:

- Domain Name: `study.activesales.uz` → IP `192.168.122.10`, Port `80`

Шлюз (Traefik провайдера) выпустит Let's Encrypt и начнёт форвардить на наш edge. Пока этого
нет, домен резолвится, но шлюз отвечает `404` с дефолтным сертификатом TRAEFIK — DNS-запись
сама по себе трафик не заводит, 80/443 держит шлюз, а не VPS. Проверка: сертификат должен быть
выпущен на `study.activesales.uz`, а не «TRAEFIK DEFAULT CERT».

После подключения — прогнать проверки из раздела 4.

**Дальше по SEO (для каждого нового домена):**
- Google Search Console: добавить ресурс, подтвердить (удобнее DNS-TXT в своей зоне — HTML-тег
  в коде один на все домены), проверить отчёт hreflang.
- Яндекс.Вебмастер — критично для `.ru` и полезно для `.uz`/`.by`: добавить ресурс, подтвердить,
  **задать регион сайта** (в Яндексе гео задаётся там, hreflang он для этого не использует).
- Заполнить вкладку домена в `/admin/seo`: свой код подтверждения прав, гео-заголовок главной,
  местный телефон поддержки. Пустые поля наследуются от общих настроек.
- Юрист: проверить страновые приложения к оферте и политике (см. 2.4) до старта продаж в стране.

## 2. Что уже сделано в коде (ветка `feat/multi-domain`)

### 2.1 Самостоятельность доменов (сессии)
- `AUTH_URL` убран из `deploy/docker-compose.prod.yml` и `.github/workflows/deploy.yml`:
  он пиннил Auth.js на один домен. Базовый URL берётся из заголовков (`trustHost: true`).
- `/api/auth` выведен из matcher `src/middleware.ts` — там middleware Auth.js ставил второй
  cookie `callback-url=https://0.0.0.0:3000`, перебивавший host-based значение.
- Куки `salesup.session-token` скоупятся по хосту → вход на `.kz` не даёт сессию на `.by`.

### 2.2 SEO по странам (`src/lib/seo/site.ts`, `site-hosts.ts`)
- `siteOrigin()` — origin из заголовка запроса; `metadataBase` в `src/app/layout.tsx` берётся
  оттуда, поэтому относительные canonical на публичных страницах становятся **self-canonical**.
- `alternatesFor(path)` — взаимный hreflang `ru-BY` / `ru-KZ` / `ru-RU` / `ru-UZ` (+ `kk-KZ`
  для казахской версии) и `x-default` на `.by`;
  проставлен на `/`, `/courses`, `/courses/[slug]`, `/business`, `/offer`, `/offer-b2b`, `/privacy`.
  Карточка курса с ручным `canonicalPath` (склейка) hreflang не получает — это осознанно.
- `sitemap.ts`, `robots.ts`, `llms.txt` — свои на каждом домене; JSON-LD каталога и карточки
  курса ссылаются на свой домен; `areaServed` организации = страна домена.
- Приватные зоны (`(student)/app`, `(owner)/admin`, `(auth)`) получили явный `noindex`.
- Аналитика: `isOwnHost()` — переход между нашими доменами больше не считается внешним
  реферером (`src/app/api/track/route.ts`).

### 2.3 Ресурсы: микрокэш вместо потерянного ISR
Host-aware метаданные сделали публичные страницы динамическими, поэтому витрину кэширует nginx
(`deploy/proxy_cache_public.conf`, зона в `nginx.http.conf`/`nginx.conf`):
ключ `$scheme$host$request_uri` (домен обязателен в ключе, иначе `.kz` получил бы страницу,
отрендеренную для `.by`), 60 с + stale-while-revalidate, обход кэша при cookie сессии,
ответы с `Set-Cookie` не кэшируются. Кэшируются только `/`, `/courses*`, `/business`, `/offer`,
`/offer-b2b`, `/privacy`, `sitemap.xml`, `robots.txt`, `llms.txt`.

### 2.4 Документы под страну (`src/content/legal/country.ts`)
Исполнитель один и зарегистрирован в РБ, поэтому основной текст оферты и политики остаётся
белорусским, а под домен подставляется **приложение**: императивные нормы местного закона о
защите прав потребителей, местный закон о ПДн, трансграничная передача на серверы в РБ, валюта
витрины и куда жаловаться. Домен внутри текста — тот, на котором документ читают.
Версия акцепта у страновых редакций своя: `1.1-KZ`, `1.1-RU`, `1.1-UZ` (`acceptedLegalVersion()`
пишется в `User.termsVersion` и `Lead.consentVersion`).
Ручной текст в `/admin/seo` перекрывает документ целиком и сразу на всех доменах — в форме об
этом написано.

### 2.4a Языки доменов (`src/i18n/routing.ts`)
Русский — язык по умолчанию, без префикса. Второй язык домена живёт под префиксом:
казахский `/kk` на `.kz`, узбекский `/uz` на `.uz`. Привязка языка к хосту — в `HOST_LOCALE`,
переведённые страницы — в `TRANSLATED_PATHS`. Непереведённый путь под префиксом уводится
на русскую версию и не попадает в hreflang, поэтому поисковик не видит локальный адрес
с русским текстом. Карточки курсов открыты на всех языках (интерфейс переведён, содержимое
курса приходит из БД на русском), но канонизируются на русский адрес и в hreflang не идут.

Добавить язык = строка в `HOST_LOCALE` и `TRANSLATED_PATHS` + `<lang>.ts` рядом с русским
контентом (`landing`, `courses-page`, `business`) + секция в `src/i18n/messages.ts`.

### 2.5 Переключатель стран
`src/components/landing/country-switcher.tsx` в футере: ссылки на текущий путь других доменов
с `rel="alternate"` + `hreflang`, текущая страна выделена. Это и удобство, и взаимные ссылки
между региональными версиями. В кабинете его нет — переход меняет домен, а значит и сессию.

### 2.6 Edge (сделано на сервере)
`~/infra/conf.d/study.conf`: `server_name` расширен на три хоста, жёсткие
`Host: study.activesales.by` и `X-Forwarded-Host: study.activesales.by` заменены на `$host`.
Бэкап рядом — `study.conf.bak-<дата>`. Внутренний nginx проекта слушает `server_name _` и
пробрасывает `Host $http_host`, менять его не потребовалось.

## 3. Что осознанно осталось на канонический `.by`
- Ссылки в письмах, PDF-сертификатах и QR `/verify` — сертификат должен проверяться по одному
  постоянному адресу независимо от того, с какого домена учился ученик.
- `NEXT_PUBLIC_SITE_URL` (build-time) — фолбэк для неизвестного хоста и адрес в админке.
- Юрлицо, реквизиты и применимое право — РБ на всех доменах.

## 4. Проверки после «Add Domain»
Пункты с ⟨host⟩ — для нового домена, плюс регресс на уже работающих.

- [ ] `https://⟨host⟩/api/health` → `{"status":"ok","db":"up"}`, сертификат Let's Encrypt (не TRAEFIK).
- [ ] `https://⟨host⟩/api/auth/csrf` → callback-url только своего домена (нет `0.0.0.0`, нет чужого).
- [ ] `/app` без сессии → редирект на `https://⟨host⟩/login`; вход держит сессию на своём домене,
      и вход на одном домене не даёт доступа на другом.
- [ ] `view-source` главной: `canonical` = свой домен, `alternate` на все домены + `x-default`.
- [ ] Цены на витрине — в валюте страны домена и только в ней (₸ / ₽ / Br / сум).
- [ ] `/sitemap.xml` и `/robots.txt` содержат свой домен; `/llms.txt` — свой домен и свою страну.
- [ ] `/offer` и `/privacy` заканчиваются страновым приложением, в шапке — версия `1.1-<код>`;
      на `.by` приложения нет (основной текст и так белорусский).
- [ ] Футер: активна своя страна, ссылки ведут на тот же путь других доменов.
- [ ] Видео, AES-ключ и субтитры играют на всех доменах.
- [ ] `curl -I` публичной страницы дважды → второй ответ `X-Cache-Status: HIT`; на странице с
      cookie сессии — `BYPASS`.
- [ ] `/app`, `/admin`, `/login` отдают `noindex`.

## 5. Откат
- Проблема с одним доменом → удалить его в панели + снять DNS; остальные не затронуты.
- Регресс логина после снятия `AUTH_URL` → вернуть переменную в env (быстрый откат).
- Регресс SEO → `siteOrigin()` уже падает на `NEXT_PUBLIC_SITE_URL`; чтобы вернуть прежнее
  поведение целиком, достаточно вернуть `metadataBase` на env-значение.
- Микрокэш мешает → убрать `include proxy_cache_public.conf` из закэшированных location и reload.
- Edge → `cp ~/infra/conf.d/study.conf.bak-<дата> ~/infra/conf.d/study.conf && nginx -s reload`.

## 6. Риски и заметки
- **Ресурсы:** дополнительные домены не добавляют контейнеров; микрокэш держит нагрузку на
  уровне одного домена, кэш — 128 МБ на диске контейнера nginx.
- **Auth.js beta:** host-детект может меняться между версиями — покрыт проверками раздела 4.
- **Правовая рамка.** ПДн минимизированы, поэтому инфраструктура в каждой стране не
  разворачивается. Открытые вопросы, которые стоит держать в поле зрения:
  - РК: закон о ПДн требует хранения данных граждан РК на территории РК — минимизация снижает
    объём риска, но не обнуляет; готовность к переезду сохраняется (`docs/MIGRATION.md`).
  - РФ: 152-ФЗ относит к ПДн в том числе e-mail и логин, то есть учётки российских учеников
    формально попадают под требование локализации, а сервер вне РФ; иностранный оператор
    формально уведомляет Роскомнадзор о начале обработки. Публичная витрина без форм вне этого
    риска. Решение по обслуживанию российских учеников — за владельцем.
  - УЗ: Закон № ЗРУ-547 требует, чтобы база персональных данных граждан Узбекистана
    размещалась на территории страны (норма 2021 года). Ограничение того же рода, что в РК
    и РФ: минимизация ПДн снижает объём риска, но не снимает его. Решение — за владельцем.
  - Страновые приложения к документам — рабочая редакция, нужна проверка юристом.
