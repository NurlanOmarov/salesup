# MIGRATION.md — переезд DatabaseMart → ps.kz / hoster.kz (заготовка)

> 📄 Конкретный исполняемый runbook переезда на новый VPS `93.127.131.216` (edge-nginx + поддомен `study.activesales.by` + TLS) — [MIGRATION-RUNBOOK.md](MIGRATION-RUNBOOK.md). Ниже — общий каркас.
>
> ⚠️ Это каркас. Полный проверенный runbook — задача **S6.5** (BACKLOG, Спринт 6): дописывается и прогоняется на тестовом VPS до запуска. Цель — простой ≤ 30 мин.
> Мотивация переезда: закон РК «О персональных данных» требует хранения БД с ПДн на территории РК (см. DECISIONS.md D-003).

## Предпосылки, заложенные в код (проверять при ревью каждой фичи)

- Все медиа адресуются **относительными ключами** через `lib/storage` (`courses/<slug>/lessons/<id>/...`); абсолютных путей нет нигде, включая БД и логи.
- Интерфейс `lib/storage` имеет драйвер `fs` (текущий) и заглушку `s3` (вариант А: S3 ps.kz) — смена = `STORAGE_DRIVER` в env.
- Весь стек — Docker Compose; состояние только в двух местах: PostgreSQL (volume `pgdata`) и медиа (volume `media`).
- Бэкапы (S6.3): ночной шифрованный `pg_dump` + rsync-манифест медиа — то же самое используется при переезде.

## План (вариант Б → Б: диск нового VPS)

1. **Подготовка (за несколько дней):** заказать VPS ps.kz/hoster.kz (≥2 vCPU / 4 ГБ / диск с запасом под видеотеку); поставить Docker + compose, пользователя deploy, SSH-ключи, ufw, fail2ban (как P0.1); понизить TTL DNS-записей до 300 с.
2. **Предсинхронизация медиа (без простоя):** `rsync -a` каталога media на новый сервер; повторять до даты переезда (дельты — минуты).
3. **Окно переезда:** включить maintenance-страницу на старом nginx → финальный `pg_dump` → restore на новом сервере → финальный `rsync` дельты media → `docker compose up -d` на новом сервере → smoke-чеклист (логин, видео+ключ, тест, сертификат, /verify, админка).
4. **Переключение:** смена A-записи домена → проверка TLS (certbot) → мониторинг логов 24 ч.
5. **После:** вернуть TTL, новый сервер — в расписание бэкапов, старый VPS держать read-only 1–2 недели, затем затереть (ПДн!).

## Вариант Б → А (опционально, медиа в S3 ps.kz)

1. Реализовать драйвер `s3` в `lib/storage` (интерфейс готов).
2. Фоновая синхронизация media → S3 bucket (скрипт по манифесту).
3. Переключить `STORAGE_DRIVER=s3` + S3-ключи в env → перезапуск app.
4. Откат — обратная смена драйвера (файлы на диске не удалять до стабилизации).
