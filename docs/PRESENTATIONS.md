# Презентации уроков: фирменный стиль и процесс

Документ описывает, как делать **PDF-раздатки уроков** (`pnpm factory:handout`) — те, что лежат рядом
с транскриптом в `Презентации/<Курс>/<NN-Урок>/`. Здесь же — фирменный стиль ACTIVE SALES, чтобы
новые курсы выглядели как уже выпущенные (медпреды, B2B-переговоры, тайм-менеджмент).

> Не путать с двумя другими форматами:
> * **колода в кабинете** — `AiArtifact SLIDES`, JSON в `prisma/seed-data/<курс>-content.ts`,
>   рендерится компонентом `src/components/learn/slide-deck.tsx` (вкладка «Презентация» урока);
> * **AI-презентация NotebookLM** — `pnpm factory:slides-pdf`, поле `Lesson.slidesPdfKey`,
>   дополнительный материал, генерируется внешним сервисом (квота ~2 колоды в день).
>
> Раздатка из этого документа делается локально, без внешних сервисов и без квот.

---

## 1. Процесс

```bash
# 1. Транскрипты уроков уже лежат в Презентации/<Курс>/<NN-Урок>/transcript.txt
# 2. Описываем колоды данными:
#    scripts/factory/handouts/<slug>.ts   (типы — scripts/factory/handouts/types.ts)
# 3. Печатаем PDF (headless Chrome, ассеты встраиваются в HTML как data: URI):
pnpm factory:handout --course sales-shoes            # все уроки курса
pnpm factory:handout --course sales-shoes --deck 03  # только урок, папка которого начинается с «03»
pnpm factory:handout --course sales-shoes --keep-html # оставить HTML рядом с PDF (для отладки вёрстки)
```

PDF кладётся в `Презентации/<folder>/<dir>/<file>.pdf`, где `folder`, `dir` и `file` заданы
в описании курса. Требуется установленный Google Chrome (или Chromium).

### Что нужно, чтобы добавить курс

1. Создать `scripts/factory/handouts/<slug>.ts` с экспортом `HANDOUT: CourseHandout`.
2. Указать `slug`, `folder` (папка внутри `Презентации/`), `courseTitle` (подпись в футере).
3. На каждый урок — объект `{ dir, file, slides }`.
4. Запустить `pnpm factory:handout --course <slug>` и просмотреть PDF.

Ассеты общие для всех курсов и берутся из репозитория:
`Презентации/logo-active.webp` (логотип) и `Презентации/IMG_6136-2.webp` (фото тренера).

## 2. Фирменный стиль

| Роль | Цвет |
| --- | --- |
| Фон слайда | `#F5F1EC` (тёплый кремовый) |
| Тёмный фон, карточки, обложка | `#1B2440` (графит-синий) |
| Акцент: кикеры, номера, «корона» | `#EE3239` (красный) |
| Основной текст | `#1B2440` |
| Вторичный текст | `#4B5563`, подписи — `#9CA3AF` |

* **Формат** — 1280×720 (16:9), поля 76 px, футер прибит к низу.
* **Шрифт** — системный (SF Pro / Helvetica), заголовки 800, letter-spacing отрицательный.
* **Кикер** — красная черта + КАПС красным, 15 px, letter-spacing 2.4 px. Есть на каждом слайде.
* **Заголовок** — 44 px (58 px на `statement`), ключевое слово можно подсветить красным (`highlight`).
* **Карточки** — радиус 14 px, белые с лёгкой тенью; акценты — тёмная и красная, «было» — пунктирная.
* **Футер** — логотип, название курса, `study@activesales.by`. На тёмных слайдах вместо картинки
  логотипа собирается текстовый лок-ап (красный знак + «ACTIVE SALES»), потому что логотип красный на белом.
* **Фото тренера — ровно один раз на колоду, только на обложке.** Дальше по колоде фото не повторяется:
  на слайде-цитате вместо него крупная светло-серая кавычка. Правило зашито в типах — поле `photo`
  есть только у `cover`.

### Ритм колоды

Обложка → постановка проблемы (`statement`) → 2–5 содержательных слайдов → цитата тренера →
итог (`summary`, тёмный). 6–9 слайдов на урок: раздатка — это выжимка, а не пересказ видео.

## 3. Макеты (`scripts/factory/handouts/types.ts`)

| `layout` | Когда использовать |
| --- | --- |
| `cover` | Первый слайд: кикер «Урок N · тема», заголовок, подзаголовок, фото тренера справа |
| `statement` | Одна крупная мысль урока + абзац пояснения; `watermark` — большая цифра фоном |
| `cards` | 2–3 колонки карточек: типы вопросов, методы, приёмы. `banner` — красная плашка-цитата снизу |
| `numbered` | Список 01…N в одну-две колонки: шаги, правила, ошибки (>8 пунктов верстается плотнее) |
| `strips` | Плашки-строки: последовательность этапов; `accentLast` красит последнюю красным |
| `split` | Две колонки-сравнения: «работает / не работает», «вопросы / презентация»; тона `good`, `bad`, `neutral` |
| `matrix` | 2×2: «было / стало», четыре возражения, четыре ошибки |
| `figure` | SVG-схема из `public/` + выноски справа (план зала, анатомия обуви) |
| `quote` | Цитата тренера крупно, на фоне светло-серой кавычки (без фото — оно только на обложке) |
| `summary` | Тёмный финал: «что забрать в смену», 4–5 пунктов |

Тона карточек: `light` (по умолчанию), `dark`, `red`, `dashed`.

## 4. Правила контента

1. **Только по видео.** Любой тезис должен быть в транскрипте урока; формулировки тренера
   сохраняем дословно там, где это цитата («самое дорогое — это ведь самое дешёвое»).
   Ничего не досочиняем — это то же правило, что и для заданий курса.
2. **Слайд = одна мысль.** Заголовок формулируем утверждением («Дешевле — не значит выгоднее»),
   а не темой («О цене»).
3. **Глаголы и цифры.** «Дать осмотреться 10–20 секунд» вместо «важность паузы».
4. **Реплики — в кавычках.** Продавцу нужны готовые фразы, а не пересказ.
5. **Максимум 6 карточек** или 13 пунктов на слайд; иначе — разделить на два.
6. **Схемы — из `public/images/`**, чтобы одна и та же картинка работала и в раздатке,
   и в hotspot-тренажёре урока (например `public/images/shoes/boot-anatomy.svg`).
7. **Финальный слайд** — всегда чек-лист действий на смену, а не «спасибо за внимание».

---

## 5. Проверка перед сдачей

* PDF открывается, страниц столько же, сколько слайдов в описании;
* ничего не наезжает на заголовок и футер: при 7+ плашках (`strips`), 7+ карточках (`cards`)
  и 9+ пунктах (`numbered`) генератор включает плотный режим — но длинные тексты всё равно
  проверяйте глазами, при переполнении делите слайд надвое;
* кикер, заголовок и футер есть на каждом слайде, кроме обложки;
* фото тренера встречается ровно один раз — на обложке — и не обрезано по лицу; логотип читается на своём фоне;
* цитаты совпадают с транскриптом (`Презентации/<Курс>/<урок>/transcript.txt`).

## 6. Схемы-иллюстрации (SVG) и тренажёр «Схема»

Одна и та же картинка работает в двух средах: в раздатке (белая карточка, печать)
и в hotspot-тренажёре кабинета (тёмная тема). Отсюда правила — и автоматическая
проверка, которая их сторожит:

```bash
pnpm factory:check-svg                      # все схемы в public/images
pnpm factory:check-svg --dir public/images/tourism
```

Скрипт открывает каждый SVG в headless-браузере и меряет по-настоящему:
`getComputedTextLength()` — ширину надписи, `isPointInFill()` — попадают ли её
концы в ту же фигуру, что и середина (для трапеций это учитывает скос на нужной
высоте). Возвращает код 1, если что-то не так.

**Правила схемы**

1. **Подпись не вылезает за фигуру.** Считать «на глаз» нельзя: в трапеции
   доступная ширина зависит от высоты строки. Не помещается — сокращаем реплику
   до сути или расширяем фигуру, шрифт не мельчим.
2. **Отступ от края холста ≥ 8 px** (в единицах viewBox): иначе подпись
   срезается на узком экране.
3. **Светлая подложка обязательна** — `<rect>` во всю ширину сразу после
   `</defs>`. Без неё тёмные заголовки пропадают в тёмной теме кабинета; на
   белой раздатке подложка не видна.
4. **Схема — не текст.** Реплики в фигурах короткие, длинный разбор уходит в
   точки hotspot (`points[].text`) и в выноски раздатки.
5. **Одна картинка на оба формата**: путь `public/images/<курс>/<схема>.svg`
   используется и в `HOTSPOT`-артефакте, и в `layout: "figure"` раздатки.

**Правила тренажёра «Схема»**

* `caption` в `HOTSPOT`-артефакте формулируется как **цель задания**
  («Цель — собрать воронку целиком: какие вопросы задавать…»), а не как
  инструкция: компонент сам печатает заголовок «Задание: разобрать схему по
  точкам», счётчик «N из M» и строку о том, сколько осталось.
* Точки расставляются по видимым блокам схемы; проверять их положение нужно
  глазами — на прод-размере и в тёмной теме.

**Что проверять глазами после `pnpm factory:check-svg`**

* тёмная тема кабинета: заголовки читаются, подложка не «светит» лишним полем;
* карточка точки открывается внутрь схемы (у нижних — вверх, у крайних — к
  центру) и целиком видна;
* PDF: подложка не оставляет видимой рамки на белой карточке слайда.
