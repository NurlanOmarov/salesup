## 0. Изменения версий (приоритетнее текста ниже при расхождениях)

### Версия 1.2

1. **Один сервер, без сторонних сервисов (кроме LLM API).** Весь стек — Docker Compose на одном VPS: Next.js-приложение, self-hosted PostgreSQL 16 + pgvector, nginx (TLS, защищённая раздача медиа через X-Accel-Redirect), worker-контейнер (фоновые задачи + cron). Временный хостинг — VPS DatabaseMart; целевой — казахстанский ps.kz / hoster.kz. ⚠️ Закон РК «О персональных данных» требует хранения базы с ПДн на территории РК — поэтому на временном зарубежном VPS собираем минимум данных (только логин/e-mail и имя для сертификата), а переезд в РК — приоритетная задача с готовым runbook-ом (docs/MIGRATION.md, простой ≤ 30 мин).
2. **Онлайн-оплаты в MVP нет.** Раздел 4.5 переносится в Фазу 2 целиком. Вместо чекаута: форма заявки на лендинге/странице курса (модель Lead) → владелец связывается, устно подтверждает оплату → в админке за минуту создаёт ученика (логин = e-mail, временный пароль с принудительной сменой при первом входе) и выдаёт доступы к курсам вручную (Enrollment source=MANUAL). Все действия фиксируются в AdminLog. Модели Order/Payment/PromoCode сохранены в схеме — платёжный модуль (Kaspi/Freedom Pay) включается позже без миграций.
3. **Видео — на диске самого VPS (вариант Б).** Конвейер прежний (yt-dlp + FFmpeg → HLS AES-128 локально у владельца), доставка на сервер — rsync, раздача — nginx X-Accel-Redirect после серверной проверки доступа приложением; AES-ключ — отдельный авторизованный эндпоинт. Объём: 720p ≈ 1 ГБ/час. Хранилище абстрагировано (lib/storage: драйвер fs сейчас → s3 после переезда, вариант А: S3 ps.kz от 6 ₸/ГБ), поэтому смена варианта — замена конфига, не переписывание.
4. **Мультиязычные субтитры RU / KK / EN / UZ** с переключателем в плеере: фабрика переводит очищенный русский транскрипт LLM-ом (с сохранением таймкодов и глоссарием терминов продаж), кладёт готовые VTT-дорожки рядом с HLS (модель SubtitleTrack), выборочно валидирует AI-критиком. Дорожки раздаются тем же защищённым каналом, что и видео.
5. **Аутентификация:** только логин/пароль (argon2id), без самостоятельной регистрации, OAuth и OTP в MVP; «забыли пароль» — через администратора. E-mail-рассылка опциональна (self-hosted SMTP, флаг EMAIL_ENABLED) — основные уведомления в Фазе 3 переедут в Telegram-бот, что снимает проблему доставляемости почты со своего сервера.

### Версия 1.1

1. **Полностью без участия преподавателя.** Преподаватель — только источник исходных видеозаписей (YouTube) и лицо бренда. Вся операционная работа автоматизирована: курсы собирает «фабрика курсов» (CLI-конвейер), сгенерированный контент валидирует **AI-критик** (второй LLM-проход по транскрипту) вместо человеческой модерации, на вопросы учеников отвечает AI-наставник (вопросы без ответа в материале честно помечаются и логируются как «пробелы контента»), отзывы модерирует LLM, плохой контент исправляет фидбек-петля (≥2 дизлайков → авто-регенерация). Единственная роль человека — «владелец»: задать цену, нажать «Опубликовать», обработать возврат, читать еженедельный дайджест. Раздел 4.4 читать как «консоль владельца», все упоминания модерации тренером — как «валидация AI-критиком».
2. **Вся инфраструктура — бесплатные тарифы; платим только за LLM API и комиссии платёжного провайдера.** Хостинг: Cloudflare Pages (Vercel Hobby запрещает коммерческое использование). Видео: Cloudflare R2 (10 ГБ бесплатно, исходящий трафик всегда $0) + собственный HLS-конвейер с AES-128-шифрованием вместо Bunny Stream; кодирование (FFmpeg) и скачивание с YouTube (yt-dlp) — локальный CLI, что бесплатно и надёжнее (YouTube блокирует серверные IP). Очереди: таблица в Postgres + Cloudflare Cron (вместо Inngest/Redis). БД: Supabase Free. Почта: Resend Free (100 писем/день). Мониторинг/аналитика: Sentry/PostHog Free. Честная оговорка: при росте видеотеки сверх 10 ГБ R2 стоит ~$1.5 за 100 ГБ/мес — единственная потенциально платная позиция, кроме LLM.
3. Актуальные план работ, конвенции и схема БД — в `BACKLOG.md` v1.1, `CLAUDE.md` v1.1, `schema.prisma` v1.1; разделы 8–9 ниже сохранены как обоснование архитектуры, но стек и роадмап заменены версиями из п. 1–2.

## 1. Резюме проекта

Создаётся онлайн-платформа для продажи и прохождения видеокурсов по техникам продаж в различных отраслях (туризм, мебель/кухни, обувь, недвижимость, медпредставители, B2B-переговоры и др.). На старте — один преподаватель (бизнес-тренер), каталог из ~10–30 продуктов (видеокурсы, тесты, анкеты), по образцу существующего ассортимента на activesales.by.

**Ключевое отличие от аналогов (УТП):** платформа не просто показывает видео, а превращает каждый урок в интерактивный тренажёр с помощью ИИ. Транскрипты уроков (из субтитров YouTube-записей) становятся «базой знаний» курса, на основе которой LLM:

1. ведёт **чат-наставника** по содержанию конкретного урока (отвечает только в рамках материала);
2. автоматически **генерирует тесты, кейсы и тематические задачи** под отрасль ученика;
3. **проверяет открытые ответы** ученика на соответствие методике тренера и даёт развёрнутую обратную связь;
4. проводит **симуляции продаж** («ИИ играет роль трудного клиента» — отработка возражений в диалоге);
5. формирует **персональные конспекты, чек-листы и скрипты** по итогам урока.

Таких связок «видеокурс по продажам + AI-тренажёр на материале самого тренера» на рынке СНГ практически нет — это и есть позиционирование «платформа, аналогов которой ещё нет».

**Прочие обязательные элементы:** SEO-лендинг и каталог, личные кабинеты ученика и преподавателя, оплата через Kaspi (и резервный казахстанский эквайринг), выдача верифицируемых сертификатов, многоуровневая защита контента от копирования, современный анимированный UI при максимальной простоте использования.

## 2. Анализ международного опыта: что заимствуем

### 2.1 Coursera
| Что берём | Как адаптируем |
|---|---|
| Структура «курс → модули → уроки → проверка после каждого урока» | Ядро учебной модели платформы |
| Прогресс-бар курса, недельные цели, напоминания | Виджет прогресса + e-mail/Telegram-напоминания |
| Сертификаты с уникальным URL для проверки подлинности | PDF-сертификат + публичная страница верификации с QR-кодом |
| Транскрипт под видео с кликабельными таймкодами | Транскрипт из субтитров YouTube, клик по фразе перематывает видео |
| Оценка от сокурсников (peer review) | На этапе 1 заменяем AI-проверкой открытых ответов |

### 2.2 Udemy
| Что берём | Как адаптируем |
|---|---|
| Продающая карточка курса: промо-видео, программа по урокам, «чему вы научитесь», отзывы, FAQ | Шаблон страницы курса (она же SEO-страница) |
| Q&A под каждым уроком | AI-чат по уроку + возможность задать вопрос тренеру |
| Заметки ученика с привязкой к таймкоду видео | Кнопка «Заметка» прямо в плеере |
| Скорость воспроизведения, автопереход к следующему уроку | Стандарт плеера |
| Купоны и промо-цены | Модуль промокодов |

### 2.3 MasterClass
Премиальная «киношная» подача: крупный hero-видеоблок, тёмная элегантная тема, минимализм. Заимствуем визуальный уровень лендинга и трейлеров курсов — это сильно отличает от типичных «инфобизнесовых» сайтов СНГ.

### 2.4 Duolingo / Kahoot (геймификация)
Стрики (дни подряд), XP-очки за уроки и тесты, уровни, ачивки-бейджи, мгновенная яркая обратная связка при правильном ответе (конфетти, звук, микроанимация). Дозированно, чтобы не превратить B2B-продукт в игрушку.

### 2.5 GetCourse / Skillbox (рынок СНГ)
Берём: понятный кабинет ученика «мои курсы — продолжить с места остановки», урок открывается только после прохождения теста предыдущего (настраиваемо), приём платежей локальными методами. Избегаем: перегруженного интерфейса GetCourse — наш приоритет простота.

### 2.6 Khan Academy
Принцип mastery learning: тест после каждого урока с порогом прохождения (например, 80%), возможность пересдачи, объяснение ошибок. У нас объяснение ошибок делает LLM на материале урока.

## 3. Роли пользователей

1. **Гость** — видит лендинг, каталог, страницы курсов, бесплатные демо-уроки; может купить курс (регистрация в процессе оплаты).
2. **Ученик** — личный кабинет, доступ к купленным курсам, прогресс, тесты, AI-инструменты, сертификаты, история покупок.
3. **Владелец** — единственная человеческая роль управления (v1.1): задаёт цены, публикует собранные фабрикой курсы, обрабатывает возвраты и оплаты по счёту, читает еженедельный дайджест и флаги. Контент не модерирует и на вопросы не отвечает — это делают AI-критик и AI-наставник.
4. **(Фаза 3) Корпоративный заказчик** — покупка пакета мест для отдела продаж, дашборд прогресса своих сотрудников.

## 4. Функциональные требования

### 4.1 Публичная часть (SEO)

**4.1.1 Главный лендинг**
- Hero-блок: видеофон/анимация, оффер, CTA «Выбрать курс» и «Бесплатный урок».
- Блоки: отрасли (туризм, мебель, обувь, недвижимость, B2B…), как проходит обучение (видео → AI-тренажёр → тест → сертификат), о тренере (регалии, фото/видео), отзывы, цифры (лет опыта, обученных продавцов), FAQ (аккордеон), форма заявки/контакты (Telegram/WhatsApp).
- Анимации появления при скролле, микровзаимодействия на кнопках; демонстрация AI-чата в виде интерактивного виджета прямо на лендинге («спросите ИИ о курсе»).

**4.1.2 Каталог курсов** — `/courses`
- Карточки: обложка, название, отрасль, длительность, число уроков, цена в ₸, рейтинг, бейдж «AI-тренажёр».
- Фильтры: отрасль, тип (курс / тест / анкета), цена; сортировка; поиск.

**4.1.3 Страница курса** — `/courses/[slug]` (главная SEO-единица)
- Промо-видео (трейлер), программа курока по урокам (часть уроков с пометкой «бесплатный просмотр»), «чему научитесь», для кого, формат, отзывы, сертификат-превью, FAQ, блок тренера, CTA покупки (фиксированная кнопка на мобильных).
- Schema.org разметка `Course`, `VideoObject`, `FAQPage`, `AggregateRating`, `Product/Offer`.

**4.1.4 Блог** — `/blog` (фаза 2): статьи по техникам продаж для органического трафика, перелинковка на курсы. Контент статей можно генерировать из транскриптов уроков (черновик — ИИ, финал — тренер).

**4.1.5 SEO-требования**
- SSR/SSG (Next.js), Core Web Vitals: LCP < 2.5 c, CLS < 0.1, INP < 200 мс.
- ЧПУ-URL, мета-теги и OG-изображения на каждую страницу, sitemap.xml, robots.txt, канонические URL, микроразметка, hreflang (ru, при необходимости kk).
- Регистрация в Google Search Console и Яндекс.Вебмастер; цели в GA4 + Яндекс.Метрика.

### 4.2 Аутентификация
- E-mail + пароль, вход по коду на e-mail (passwordless), OAuth Google. Опционально: вход по номеру телефона (SMS) — привычно для аудитории KZ.
- Покупка без предварительной регистрации: e-mail вводится на чекауте, аккаунт создаётся автоматически, доступ приходит письмом.
- Сессии JWT (HttpOnly cookie), refresh-токены, ограничение одновременных сессий (антишаринг, см. 4.7).

### 4.3 Личный кабинет ученика

- **Дашборд:** «Продолжить обучение» (последний урок), прогресс по каждому курсу (%), стрик, XP/уровень, ближайшая цель, рекомендации.
- **Плеер урока (ключевой экран):**
  - защищённое видео (см. 4.7), скорости 0.5–2x, качество, «с того же места»;
  - вкладки рядом/под видео: *Транскрипт* (кликабельные таймкоды, поиск по тексту), *Материалы* (PDF-чек-листы, скрипты — с водяным знаком), *Заметки* (привязаны к таймкоду), *AI-наставник* (чат по уроку), *Вопрос тренеру*;
  - по завершении видео — мягкий переход к блоку закрепления: тест/задание/симуляция.
- **Проверка знаний после урока:** тесты (один/несколько ответов, верно-неверно, соответствие, сортировка этапов продаж, заполнение пропусков в скрипте), открытые вопросы (проверяет LLM), анкеты (само-оценка до/после курса — как «Анкета до тренинга» в текущем ассортименте). Порог прохождения настраивается; пересдачи; разбор ошибок с цитатой из урока.
- **AI-инструменты** (см. раздел 5).
- **Сертификаты:** выдаётся при выполнении условий (все уроки + итоговый тест ≥ N%). PDF на фирменном бланке: ФИО, курс, часы, дата, номер, подпись тренера, QR → страница верификации `/verify/[id]`. Кнопка «Поделиться в LinkedIn/Instagram».
- **Покупки и платежи:** история, чеки, повторная покупка, продление доступа (если доступ ограничен по времени — настраивается per-курс: навсегда / 6 мес / 12 мес).
- **Профиль:** имя (для сертификата), отрасль и должность (для персонализации AI-задач), уведомления.

### 4.4 Консоль владельца (в v1.1 заменяет «кабинет преподавателя»; описание ниже — функциональный максимум, реализуется read-mostly подмножество из BACKLOG v1.1)

- **Конструктор курсов:** курс → модули → уроки; загрузка видео (или привязка к видеохостингу), обложки, материалы, цена, тип доступа, бесплатные демо-уроки, порядок, статус (черновик/опубликован).
- **Импорт транскриптов:** вставить ссылку на YouTube-видео или плейлист → система скачивает субтитры, очищает, привязывает к уроку с таймкодами (см. 5.1). Редактор транскрипта (исправление ошибок распознавания).
- **Фабрика контента (v1.1):** по транскрипту урока автоматически генерируются тест (10–15 вопросов), открытые задания, кейсы, конспект, чек-лист, сценарий симуляции. *Ничего AI-сгенерированного не публикуется без прохождения AI-критика* (валидация по транскрипту: ответ существует в уроке, однозначность, корректность; провал → авто-регенерация до 2 раз). Человек контент не просматривает; качество дополнительно поддерживает фидбек-петля дизлайков учеников.
- **Конструктор тестов/анкет** (ручной режим): все типы вопросов, баллы, порог, лимит попыток. Отдельный тип продукта «Тест» — продаётся самостоятельно (как текущие тесты для оценки продавцов), с отчётом для руководителя.
- **Ученики:** список, прогресс, результаты тестов, ответы на анкеты, ручная выдача/отзыв доступа, выгрузка CSV.
- **Продажи:** заказы, статусы оплат, промокоды, возвраты.
- **Аналитика:** выручка, конверсия страниц курсов, completion rate, точки «отвала» внутри видео (heatmap досмотров), самые сложные вопросы тестов, частые вопросы к AI-чату (→ идеи для улучшения курса).
- **Вопросы учеников:** очередь вопросов «тренеру» с контекстом (курс/урок/таймкод); черновик ответа может предлагать ИИ.

### 4.5 Оплата (Казахстан) — в v1.2 перенесено в Фазу 2; в MVP доступы выдаёт владелец вручную по заявке (Lead) после устного подтверждения оплаты

**Основной метод — Kaspi.** Варианты реализации (выбрать на этапе договорённостей с банком):
1. **Kaspi Pay (официальное партнёрство).** Требуется ИП/ТОО в РК, расчётный счёт, заявка и договор с Kaspi Bank — без договора доступ к API не дают. Даёт оплату по QR и пуш-счёт по номеру телефона, webhook о статусе. Самый конверсионный метод в KZ (Kaspi пользуется подавляющее большинство онлайн-покупателей).
2. **Агрегаторы-посредники над Kaspi** (ApiPay.kz, AiPay и т.п.) — REST API, счёт по номеру телефона, webhooks с HMAC-подписью, sandbox, фискальные чеки через Kaspi ОФД; подключение значительно быстрее, но абонентская плата и зависимость от посредника. Подходит для быстрого MVP.
3. **Резервный/дополнительный эквайринг:** Halyk Bank (ePay), Freedom Pay (paybox), CloudPayments KZ — приём карт Visa/MC/местных, рассрочка. Рекомендуется иметь минимум 2 метода: Kaspi + карты.

**Чекаут-флоу:** страница курса → «Купить» → e-mail (+ имя, телефон) → выбор метода (Kaspi / карта) → редирект или пуш-счёт → webhook «оплачено» → автосоздание аккаунта (если нового) → мгновенное открытие доступа → e-mail с доступами и чеком. Идемпотентная обработка webhooks, страница ожидания со статусом, ручная сверка в админке.

**Также:** промокоды, цены в ₸ (мультивалютность — фаза 3), фискализация чеков по законодательству РК (через ОФД-интеграцию выбранного провайдера), оферта/политика конфиденциальности/согласие на обработку ПДн.

### 4.6 Сертификаты
- Генерация PDF на сервере по шаблону (фон-бланк + переменные).
- Уникальный ID вида `AS-2026-000123`, QR-код на `/verify/[id]` — публичная страница: курс, ФИО, дата, статус «действителен».
- Сертификат появляется в кабинете + отправляется на e-mail. Опция «именной сертификат для работодателя» (указать компанию).

### 4.7 Защита контента от копирования (многоуровневая)

> 100%-й защиты видео не существует (экран всегда можно снять камерой), задача — сделать копирование максимально трудозатратным и отслеживаемым.

1. **Видео не лежит файлом (v1.1).** Собственный конвейер: yt-dlp + FFmpeg локально кодируют видео в HLS с AES-128-шифрованием, сегменты хранятся в Cloudflare R2; AES-ключ выдаётся отдельным авторизованным эндпоинтом только после серверной проверки доступа, плейлисты — с подписанными URL. Прямых mp4-ссылок не существует; нешифрованных файлов в хранилище нет. (Платный Widevine/FairPlay DRM — возможный апгрейд в будущем, в free-tier-концепцию не входит.)
2. **Подписанные одноразовые URL** с коротким TTL (1–4 часа), привязка токена к user_id и домену; hotlink-протекция, allowed referrers.
3. **Динамический водяной знак** поверх плеера: полупрозрачный e-mail/ID ученика, перемещающийся по экрану со случайным интервалом — главный сдерживающий фактор против записи экрана (утечка идентифицируется).
4. **Плеер:** отключение контекстного меню и drag, `controlsList="nodownload"`, блокировка PiP при необходимости; контент-страницы — запрет выделения/копирования текста транскрипта (CSS + JS), но с оговоркой: заметки и чек-листы скачивать можно (с водяным знаком в PDF).
5. **Антишаринг аккаунтов:** лимит активных устройств (например, 2), завершение старых сессий, алерт при входах из разных городов/IP за короткое время, rate-limit на просмотры.
6. **Поведенческая аналитика:** аномальная скорость «просмотра» всего курса, массовые обращения к сегментам — флаг в админку, возможность заморозки аккаунта.
7. **Документы (PDF):** генерируются персонализированно — на каждой странице футер «Лицензия: ФИО, e-mail, № заказа».
8. **Юридический слой:** оферта с запретом распространения, уведомление о персональном водяном знаке (само по себе снижает желание делиться).
9. **Защита текста для SEO не страдает:** публичные страницы индексируются нормально; защищается только платный кабинет.

## 5. AI-подсистема (ядро уникальности)

### 5.1 Конвейер знаний: YouTube → база знаний курса

1. Тренер вставляет ссылку на видео/плейлист YouTube (например, плейлист курса «Техники продаж в туризме»).
2. Бэкенд-воркер получает субтитры: `yt-dlp --write-auto-subs` / библиотека `youtube-transcript-api`; если субтитров нет — транскрибация аудио через Whisper API (фоллбэк).
3. Очистка LLM-ом: пунктуация, склейка фраз, исправление терминов, удаление «э-э», сохранение таймкодов на уровне абзацев.
4. Транскрипт сохраняется в БД, привязывается к уроку; делится на смысловые чанки (300–800 токенов с перекрытием), для каждого считается embedding (например, voyage / OpenAI embeddings), пишется в **pgvector** (расширение PostgreSQL — отдельная векторная БД не нужна).
5. Из чанков формируется «карта знаний» курса: ключевые техники, термины, этапы, скрипты — используется всеми AI-инструментами.

### 5.2 AI-инструменты ученика

| Инструмент | Описание | Механика |
|---|---|---|
| **Чат-наставник по уроку** | Ученик спрашивает «как ответить на возражение „дорого“ по методу из этого урока?» | RAG: вопрос → поиск релевантных чанков урока/курса → ответ Claude строго по материалу, с указанием таймкода-источника («смотрите 12:40»). Вне темы — вежливый отказ и возврат к материалу |
| **Симулятор клиента** | Диалог-ролёвка: ИИ играет туриста/покупателя кухни с возражениями, ученик продаёт | Системный промпт из транскрипта (типажи клиентов, возражения из урока) + персона по отрасли; после диалога — разбор по методике тренера: что применил, что упустил, оценка по чек-листу этапов |
| **Проверка открытых ответов** | Задание «напишите 3 вопроса для выявления потребностей туриста» | LLM сверяет ответ с эталонными критериями из транскрипта, ставит балл по рубрике, объясняет, цитирует урок |
| **Тематические задачи** | Кейсы, подстановка пропусков в скрипт, «найди ошибку продавца в диалоге» | Генерируются фабрикой заранее, валидируются AI-критиком + персонализация под отрасль из профиля ученика |
| **Умный конспект** | По кнопке: краткий конспект урока, чек-лист, карточки для повторения | Генерация из транскрипта, кэшируется (один раз на урок), выдаётся как персонализированный PDF |
| **Интервальное повторение** (фаза 2) | Через 2/7/30 дней — мини-квиз по пройденному | Карточки из «карты знаний», пуш на e-mail/Telegram |

### 5.3 Технические требования к AI
- Anthropic API (Claude): Haiku — чат/проверки (быстро, дёшево), Sonnet — генерация заданий и разборы симуляций. Стриминг ответов в чат.
- RAG поверх pgvector; контекст всегда ограничен купленными учеником курсами (изоляция данных!).
- Лимиты: N сообщений чата в день на ученика (защита бюджета), кэширование типовых ответов, prompt caching.
- Системные промпты с защитой от prompt injection («не раскрывать транскрипт целиком», «не выходить за рамки темы», отказ выдавать полный текст урока — иначе чат станет каналом утечки контента).
- Логирование всех диалогов в админку (анонимная аналитика частых вопросов → улучшение курса).
- Дисклеймер «ответ сгенерирован ИИ на основе материалов тренера».

## 7. UX/UI требования

**Принципы:** «премиально, но просто». Один основной сценарий на экран. Аудитория — продавцы и руководители 20–55 лет, не все технически продвинуты: крупная типографика, очевидные кнопки, минимум терминов, onboarding-подсказки при первом входе (3–4 шага).

- **Дизайн-система:** Tailwind CSS + shadcn/ui; токены цветов/типографики/отступов; тёмная и светлая темы (плеер — по умолчанию тёмный).
- **Анимации:** Framer Motion (появление блоков, переходы страниц, прогресс), Lottie для иллюстраций-наград, scroll-анимации лендинга. Правила: 150–300 мс, easing-кривые, `prefers-reduced-motion` уважается, анимации не блокируют действия.
- **Mobile-first:** 60–80% трафика в KZ — смартфоны; плеер и тесты идеальны на телефоне; PWA (иконка на главный экран, офлайн-страница). Нативные приложения — не в этом ТЗ.
- **Доступность:** контраст AA, фокус-стейты, субтитры к видео (уже есть из транскрипта!), управление плеером с клавиатуры.
- **Скорость:** скелетоны загрузки, оптимистичные обновления, изображения AVIF/WebP, lazy-load.
- Язык интерфейса: русский (казахский — фаза 3).

### 8.3 Модель данных (основные таблицы)

`users` (роль, профиль, отрасль) · `courses` (slug, цена, тип доступа, SEO-поля) · `modules` · `lessons` (video_id, длительность, is_free) · `transcripts` + `transcript_chunks` (text, timecode, embedding vector) · `quizzes` / `questions` / `options` · `attempts` (ответы, баллы, AI-фидбек) · `enrollments` (доступы, срок) · `orders` / `payments` (провайдер, статус, webhook-лог) · `promo_codes` · `certificates` (номер, pdf_url, verify-hash) · `progress` (lesson, позиция в секундах, completed) · `notes` · `ai_conversations` / `ai_messages` · `simulations` (сценарий, лог, разбор) · `gamification` (xp, streak, badges) · `devices/sessions` (антишаринг) · `events` (аналитика).

## 10. Нефункциональные требования и метрики

- Аптайм ≥ 99.5%; ответ страниц < 300 мс (SSR), видео-старт < 2 с.
- Масштаб: до 10 000 учеников / 500 одновременных просмотров без изменения архитектуры (CDN-видео это позволяет).
- Бюджет на старте (v1.1): инфраструктура **$0/мес** (free-tier Cloudflare Pages/R2, Supabase, Resend, Sentry, PostHog) + Anthropic API ~$20–150/мес (генерация курсов разовая, далее — чат/проверки по лимитам) + комиссии платёжного провайдера с продаж. При росте видеотеки сверх 10 ГБ — R2 ~$1.5/100 ГБ/мес.
- **KPI продукта:** конверсия страницы курса в покупку ≥ 2–4%; completion rate курсов ≥ 50% (отрасль: 10–15% — AI-интерактив должен поднять); NPS ≥ 50; доля учеников, использующих AI-чат ≥ 60%; возвраты < 2%.

| Авто-контент без человека содержит ошибку | Двухпроходная генерация (генератор + критик), порог критика ≥80, авто-регенерация, выборочная сверка владельцем первых курсов как калибровка |
| Превышение free-tier лимитов (БД 500 МБ, R2 10 ГБ, 100 писем/день) | Алерты в дайджест при >80%, батчинг писем, 720p-кодирование; платный апгрейд — копейки и предусмотрен |
| AI-чат как канал утечки транскрипта | Запрет выдачи длинных фрагментов, лимиты сообщений, детект «перескажи весь урок» |
| Рост расходов на LLM | Haiku по умолчанию, prompt caching, дневные лимиты, кэш конспектов |
| Перегруз интерфейса фичами | Поэтапный запуск, onboarding, скрытие продвинутых функций за «ещё» |
| Один разработчик — bus-factor | Документация в репо, IaC-минимум, managed-сервисы, бэкапы |

## 12. Definition of Done (MVP)

Платформа считается готовой к запуску, когда: гость находит курс из поиска → покупает через Kaspi за < 2 минут → сразу смотрит защищённое видео с водяным знаком → проходит тест → получает сертификат с рабочей верификацией → тренер видит заказ, прогресс и результаты в админке → все письма доходят → Lighthouse ≥ 90 (SEO/Perf) на лендинге и странице курса → критические флоу покрыты e2e-тестами.
