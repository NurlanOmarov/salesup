# Уведомления о заявках в Telegram

Когда с сайта приходит заявка (форма на лендинге, странице курса или `/business`),
приложение сохраняет `Lead` и ставит в очередь задачу `telegram.send`. Сообщение
отправляет worker-контейнер (задержка до ~5 секунд — интервал опроса очереди).

Если бот не настроен, отправка молча пропускается: заявка всё равно видна в
`/admin/leads` и попадает в еженедельный дайджест.

## 1. Создать бота

1. Открыть в Telegram [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Ввести имя бота (любое, например `ACTIVE SALES заявки`).
3. Ввести username — обязан заканчиваться на `bot`, например `active_sales_leads_bot`.
4. BotFather пришлёт токен вида `8123456789:AAH8n...` — это `TELEGRAM_BOT_TOKEN`.
   Токен = полный доступ к боту, хранить как пароль (только в secrets, не в git).

## 2. Узнать chat id

**Личные сообщения (уведомления приходят вам в личку):**

1. Написать своему боту любое сообщение (`/start`) — без этого бот не может писать первым.
2. Открыть [@userinfobot](https://t.me/userinfobot) → он пришлёт ваш `Id` (число вроде `123456789`).
   Это `TELEGRAM_CHAT_ID`.

Альтернатива без сторонних ботов: после `/start` открыть в браузере
`https://api.telegram.org/bot<ТОКЕН>/getUpdates` и взять `result[0].message.chat.id`.

**Группа (если уведомления нужны нескольким людям):**

1. Создать группу, добавить в неё бота.
2. Написать в группе любое сообщение.
3. Открыть `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и взять `chat.id` —
   у групп он отрицательный (например `-1001234567890`), минус обязателен.

## 3. Прописать секреты

**На проде** — GitHub → Settings → Secrets and variables → Actions → New repository secret:

| Секрет | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен от BotFather |
| `TELEGRAM_CHAT_ID` | id из шага 2 |

Дальше `git push origin main` — деплой сам положит их в `.env` на сервере и
перезапустит контейнеры.

**Локально** — те же две строки в `.env` (образец в `.env.example`).

## 4. Проверить

Отправить тестовую заявку с сайта — сообщение должно прийти в течение ~5 секунд.
Если не пришло:

```bash
docker compose -f docker-compose.prod.yml --env-file .env logs --tail=50 worker
```

- `telegram.send пропущен: бот не настроен` — секреты не доехали до контейнера;
- `telegram sendMessage 400: ... chat not found` — неверный chat id (для группы забыт минус);
- `telegram sendMessage 401` — неверный токен;
- `telegram sendMessage 403: bot was blocked by the user` — вы не нажали `/start` или заблокировали бота.

Задача остаётся в очереди и повторяется до 3 раз, так что после починки секретов
уведомление может прийти самостоятельно.

## Почта (опционально)

Уведомление можно дублировать письмом: секреты `EMAIL_ENABLED=true`, `SMTP_HOST`,
`SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`, адрес получателя —
`LEADS_NOTIFY_EMAIL`. Для Gmail нужен **пароль приложения** (Google Account →
Безопасность → Двухэтапная аутентификация → Пароли приложений), обычный пароль от
аккаунта SMTP не примет: `smtp.gmail.com`, порт `465`, `SMTP_USER` = адрес Gmail,
`SMTP_FROM` = он же.
