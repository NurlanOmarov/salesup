# UI-KIT-PLAN — заимствование компонентов из Magic UI / KokonutUI / React Bits

План точечного переноса анимированных компонентов в ACTIVE SALES. Ни одна из трёх
библиотек не подключается как зависимость: все три — копипаст-каталоги, мы берём
исходник, переписываем под наши токены и кладём в свою структуру.

Оценка библиотек и причины отказа от остальных (daisyUI, Bklit UI, Rive, anime.js)
— в конце документа.

---

## 1. Правила адаптации

Эти правила действуют для любого заимствованного компонента.

**R1. Импорт анимаций.** В исходниках Magic UI и KokonutUI импорт из `motion/react`
(пакет `motion`). У нас стоит `framer-motion@12` — это тот же код после ребрендинга.
Меняем строку импорта на `from "framer-motion"`, API не трогаем. Пакет `motion`
не ставим — два имени одной библиотеки в `package.json` не нужны.

**R2. Нет `animate-in`.** У нас не подключён ни `tailwindcss-animate`, ни
`tw-animate-css`. Классы `animate-in`, `fade-in`, `slide-in-from-*`, `zoom-in`,
`delay-(--var)` из исходников **не работают молча** — визуально просто ничего не
происходит. Заменяем на CSS-кейфреймы в `globals.css` или на framer-motion.

**R3. Цвета — только наши токены.** Выкидываем все `zinc-*`, `indigo-*`, `#06060f`
и прочие захардкоженные hex.

| Контекст | Чем красим |
|---|---|
| Маркетинг (лендинг, каталог, /verify) | `brand`, `brand-strong` (текст на светлом), `brand-light` (текст на тёмном) |
| Кабинет, геймификация | `amber-*` — продуктовый цвет прогресса |
| Успех / достигнуто | `emerald-*` |
| Ошибки | `red-*` / `rose-*` |
| Нейтраль | `foreground/NN`, `bg-background`, `border-foreground/10` |

Границы зафиксированы комментарием в [`globals.css`](../src/app/globals.css) —
красный это бренд, янтарь это геймификация, смешивать нельзя.

**R4. Тёмная тема.** У нас класс `.dark` на `<html>` (ставит `ThemeScript`) плюс
фоллбэк на `prefers-color-scheme` для случая, когда пользователь не выбирал.
Утилиты `dark:` работают, но захардкоженные тёмные фоны (`dark:bg-[#06060f]`)
меняем на `bg-background`.

**R5. `prefers-reduced-motion` обязателен.** CSS-анимации гасим в общем блоке в
конце `globals.css`. В клиентских компонентах — хук `useReducedMotion()` из
framer-motion (уже применяется в `faq.tsx`, `ai-demo.tsx`, `stat-counter.tsx`,
`industries-marquee.tsx`).

**R6. Не ломать RSC-границу.** Серверный компонент не переводится в клиентский
ради анимации. Если эффект достижим на CSS — делаем CSS. Прецедент: секция
форматов на лендинге получила подсветку карточек на `:has()` + псевдоэлементах и
осталась серверной. `"use client"` оправдан только там, где нужен стейт, курсор
или скролл.

**R7. Куда класть файлы.** Каталога `src/components/magicui/` не заводим —
он бы честно сообщал, что компоненты чужие и их никто не адаптировал.
Общего назначения → `src/components/ui/`. Узкого → рядом с местом использования
(`landing/`, `gamification/`, `learn/`).

**R8. Язык.** UI и комментарии — русский, код и коммиты — английский.

**R9. Лицензии.** Magic UI и KokonutUI — чистый MIT. React Bits — MIT + Commons
Clause: использовать в продукте можно (в том числе коммерчески), нельзя
перепродавать сами компоненты. Нам это не мешает. В шапку заимствованного файла
— строка вида `// Адаптировано из Magic UI (MIT): <url>`.

**R10. Ноль новых зависимостей.** Разрешено опираться только на то, что уже стоит:
`framer-motion`, `lucide-react`, `canvas-confetti`. Всё, что тянет `gsap`, `ogl`,
`three`, `lenis`, `cobe`, `@number-flow/react` — либо отклоняем, либо переписываем
на своих средствах.

### Чек-лист на один компонент

1. Прочитать исходник целиком, выписать импорты.
2. Прогнать по R10 — нет ли новых зависимостей.
3. Заменить импорт `motion/react` (R1), вычистить `animate-in` (R2).
4. Перекрасить по R3, проверить тёмную тему (R4).
5. Решить: CSS или клиент (R6). Если CSS — анимация уезжает в `globals.css`.
6. Добавить reduced-motion (R5).
7. Русские подписи и комментарий-атрибуцию (R8, R9).
8. `pnpm lint && pnpm typecheck`.

## 2. Волна 1 — кабинет ученика

Здесь эффект наибольший: ученик смотрит на эти экраны каждый день, и все четыре
пункта — не декор, а обратная связь о прогрессе.

### 1.1. Анимация заполнения кольца недели

**Цель:** [`weekly-goal.tsx`](../src/components/gamification/weekly-goal.tsx)
**Источник идеи:** Magic UI `animated-circular-progress-bar`

Компонент Magic UI **не копируем**: у нас уже есть кольцо на чистом SVG, серверное
и без лишнего кода. Не хватает только одного — оно появляется сразу заполненным,
потому что при SSR нет перехода от начального состояния.

Берём именно приём: анимируем `stroke-dashoffset` от полной окружности до целевого
значения через CSS-кейфрейм, целевое значение передаём инлайновой переменной.
Компонент остаётся серверным, клиентского JS ноль.

```css
@keyframes ring-fill { from { stroke-dashoffset: var(--ring-c); } }
.ring-progress { animation: ring-fill 0.9s cubic-bezier(0.22, 1, 0.36, 1) both; }
```

Объём: ~10 строк в `globals.css`, 2 строки в компоненте. Риск нулевой.

### 1.2. Анимация XP-полосы

**Цель:** [`progress-panel.tsx:61`](../src/components/gamification/progress-panel.tsx#L61)

Та же болезнь: на полосе висит `transition-all`, но при серверном рендере ширина
приезжает сразу финальной, и переход не срабатывает ни разу. Лечится тем же
кейфреймом от `width: 0`. Остаётся серверным.

Объём: ~8 строк CSS, 1 строка в компоненте.

### 1.3. Состояние «наставник думает»

**Цель:** [`tutor-chat.tsx:96`](../src/components/learn/tutor-chat.tsx#L96)
**Источник:** KokonutUI `ai-text-loading` / Magic UI `animated-shiny-text`

Сейчас на месте ожидания ответа стоит статичный текст «Думаю…». Заменяем на
бегущий шиммер по тексту (`background-clip: text` + движущийся градиент) — приём
из обоих исходников, реализация на CSS в 12 строк, без framer-motion, хотя
компонент и так клиентский.

Важно: ответ AI приходит за секунды, и статичная подпись читается как зависание.
Это единственный пункт волны, который влияет на воспринимаемую скорость продукта.

### 1.4. Конфетти при получении сертификата

**Цель:** [`certificates/page.tsx`](../src/app/(student)/app/certificates/page.tsx)

`canvas-confetti` уже стоит и уже вызывается при сдаче теста в
[`quiz-runner.tsx:74`](../src/components/quiz/quiz-runner.tsx#L74). Обёртка из
Magic UI не нужна — там ровно тот же вызов, завёрнутый в компонент.

Нужен маленький клиентский триггер и — обязательно — защита от повторов:
конфетти должно срабатывать один раз на новый сертификат, а не при каждом заходе
на страницу. Ключ выданного сертификата пишем в `localStorage`.

Объём: ~25 строк, новый клиентский компонент `certificate-celebration.tsx`.

**Проверка волны:** `pnpm lint && pnpm typecheck`; вручную — с включённым
«уменьшить движение» в системе все четыре анимации должны исчезнуть, а не
замедлиться.

## 3. Волна 2 — экран урока

### 2.1. Подвижный индикатор вкладок

**Цель:** [`lesson-tabs.tsx:263`](../src/components/learn/lesson-tabs.tsx#L263)
**Источник:** KokonutUI `smooth-tab`

Активная вкладка сейчас переключается мгновенно. Добавляем «переезжающую»
подложку через `layoutId` framer-motion.

Осторожно: файл на 522 строки и содержит всю логику вкладок урока. Трогаем
**только** разметку кнопок в шапке (строки ~225–277), логику `setTab` не касаемся.

### 2.2. Настоящий 3D-переворот флеш-карточек

**Цель:** [`flashcards-deck.tsx`](../src/components/learn/flashcards-deck.tsx)
**Источник:** KokonutUI `card-flip`

У нас `perspective: 1000` уже задан ([строка 55](../src/components/learn/flashcards-deck.tsx#L55)),
но самого `rotateY` нет — стороны меняются через `AnimatePresence`, то есть
переворота как такового не происходит. Добавляем `rotateY` + `backface-visibility`,
и заявленная перспектива наконец начинает работать.

### 2.3. Полоса прогресса чтения урока

**Источник:** Magic UI `scroll-progress`

Адаптация: убрать фирменный градиент `#A97CF8 → #FDCC92`, поставить `bg-amber-500`;
`fixed top-0` заменить на позицию под шапкой урока, иначе полоса уедет под неё.

Спорный пункт: у урока уже есть навигация и оглавление, полоса может оказаться
лишним шумом. Делать последней в волне и оценить на живом экране.

| Что | Источник | Куда | Комментарий |

## 5. Что не берём

- **Всё на тяжёлых движках.** React Bits: WebGL-фоны (`Aurora`, `Threads`, `Prism`,
  `Galaxy`, `LiquidEther` — тянут `ogl`; `Beams` — `three` + `@react-three/fiber` +
  `drei`), gsap-компоненты (`ScrollReveal`, `Masonry`, `CardSwap`, `MagicBento`),
  `ScrollStack` (Lenis перехватывает нативный скролл). Magic UI: `globe` (cobe),
  `icon-cloud`, `particles`, `warp-background`.
- **Дублирующее наше.** `number-ticker`, `marquee`, `text-animate`,
  `typing-animation`, React Bits `CountUp`, `LogoLoop` — у нас уже есть
  `stat-counter.tsx`, `industries-marquee.tsx`, `hero-word-stream.tsx`.
- **Dev-эстетика.** `terminal`, `file-tree`, `code-comparison`, моки устройств
  (`iphone`, `safari`, `android`) — язык лендинга для разработчиков, не для
  продавцов.
- **KokonutUI `hold-button` на CTA.** Удержание кнопки — лишнее трение на главном
  действии страницы.
- **Библиотеки целиком:** daisyUI (второй набор компонентных классов поверх
  shadcn + конфликт систем темизации), Bklit UI (visx/d3 вторым движком графиков
  рядом с recharts, плюс зависимость на `@base-ui/react` в alpha), Rive (~860 КБ
  рантайма и ручной труд в проприетарном редакторе от $9/seat — противоречит
  принципу zero-touch), anime.js (второй движок анимаций; вернуться, только если
  появится задача с SVG-морфингом или рисованием по контуру).

## 6. Приёмка

После каждой волны:

- `pnpm lint && pnpm typecheck` — обязательно;
- обязательные e2e из `CLAUDE.md` не должны сломаться (волна 2 задевает экран
  урока, волна 1 — кабинет);
- клиентский JS лендинга не должен вырасти: волны 1 и 2 добавляют его только в уже
  клиентские компоненты, волна 3 — единственная, где прирост нужно считать;
- ручная проверка `prefers-reduced-motion` и тёмной темы.

Порядок: волна 1 целиком за один заход, волны 2 и 3 — по решению после того, как
первая отработает на живых учениках.
